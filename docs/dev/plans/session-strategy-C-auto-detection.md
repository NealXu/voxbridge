# 方案 C：智能检测 (Auto-Detection)

## 概述

**核心思想**：根据用户输入内容自动推断目标目录/项目

```
用户输入 → NLP 分析 → 关键词提取 → 匹配项目 → 路由到对应 CC 实例

"帮我在 my-app 项目里添加登录" → 匹配 "my-app" → D:\Projects\my-app
```

**关键特性**：零配置，用户无需显式切换

---

## 设计详情

### 数据结构

```typescript
interface AutoDetectionManager {
  /** 进程池 */
  registry: ExecutorRegistry;
  
  /** 已注册项目（可被发现） */
  projects: Map<string, ProjectMeta>;
  
  /** 关键词到项目的映射 */
  keywordIndex: Map<string, string>;  // keyword → cwd
  
  /** 当前活跃目录 */
  activeCwd: string;
}

interface ProjectMeta {
  cwd: string;
  name: string;
  tags: string[];      // 用于关键词匹配
  lastUsedAt: number;
  useCount: number;
}

interface DetectionResult {
  source: "explicit" | "keyword" | "history" | "terminal";
  confidence: number;  // 0-1
  cwd: string;
}
```

### 检测流程

```
用户输入："帮我在 my-app 里添加登录功能"
    ↓
Step 1: 明确路径检测
    检查是否包含绝对路径
    结果：无
    ↓
Step 2: 关键词匹配
    分词：["帮", "我", "my-app", "里", "添加", "登录"]
    匹配："my-app" → D:\Projects\my-app
    置信度：0.9
    ↓
Step 3: 历史记录（置信度不足时）
    检查最近使用目录
    ↓
最终结果：D:\Projects\my-app
```

## 优缺点

### 优点

- ✅ 零配置
- ✅ 智能便捷
- ✅ 自然交互

### 缺点

- ❌ 推断可能不准确
- ❌ 需要关键词库
- ❌ 新项目需发现

---

## 适用场景

- ✅ 项目数量较多
- ✅ 用户习惯在输入中提及项目名
- ✅ 希望减少显式切换操作
- ❌ 需要精确控制 → 使用方案 A 或 B
